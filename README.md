Демонстрационный репозиторий сквозных (E2E) тестов для платформы **OmniNotice**. 
Проект включает в себя UI-тесты «глазами пользователя» и быстрые API-тесты.

## 🎥 Демонстрация

На видео показано, как автоматизация логинится, заполняет форму, нажимает «Отправить» и **фиксирует баг** в текущей версии фронтенда (отправка неверного контракта).

## 🐛 Статус UI-разработки (Найдено автоматизацией)

В ходе разработки UI-теста было выявлено, что текущая версия фронтенда **отправляет неверный контракт** в API Вишенки.

- **Симптом:** При нажатии «Отправить» появляется ошибка.
- **Доказательство (Network):** Фронт отправляет запрос без обязательных полей `event_id`, `account_id`, `recipients`, `created_at`.
- **Ответ бэкенда:** `422 Unprocessable Content`.
- **Причина:** Фронтенд находится в стадии активной разработки (интеграция с сервисами еще не завершена).
- **Действие:** E2E-тест успешно зафиксировал это состояние. Когда фронтенд добавит недостающие поля, тест упадет, сигнализируя о том, что сценарий готов к проверке «Happy Path».

## 🚀 Как запустить локально

### 1. Установка
```bash
npm install
npx playwright install chromium
2. Настройка
Скопируйте шаблон и заполните данные:

bash
cp .env.example .env.dev
В .env.dev укажите ваш DELEGATED_TOKEN (для API) и логин/пароль (для UI).

3. Запуск тестов
bash
# Запустить UI-тест (фиксация состояния)
npm run test:ui

# Запустить все тесты (UI + API)
npm test
4. Просмотр отчета
В отчете доступны видеозаписи каждого шага и полные логи сетевых запросов:

bash
npm run test:report
🏗 Архитектура
tests/ui/ — Сценарии взаимодействия с интерфейсом.

auth.setup.ts — глобальная авторизация (StorageState).

happy-path.spec.ts — тест, документирующий несоответствие контракта.

tests/api/ — Проверка контрактов REST API (Playwright Request).

playwright.config.ts — Конфигурация с поддержкой записи видео и скриншотов.
